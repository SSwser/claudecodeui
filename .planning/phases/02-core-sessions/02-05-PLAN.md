<task type="auto">
  <name>Task 1: Create sessionLifecycleService with process registry</name>
  <files>server/services/sessionLifecycleService.js</files>
  <action>
  Create `server/services/sessionLifecycleService.js`:

1. **Process Registry** (in-memory Map):

- `Map<sessionId, { pid: number, provider: string, startedAt: Date }>`
- Tracks all active session processes
- Populated on session creation / resume, cleared on freeze/archive/delete

2. **registerProcess(sessionId, pid, provider)**:

- Add to in-memory registry
- Update session_state table: `status='active', process_pid=pid, updated_at=now`

3. **freezeSession(sessionId)** (D-01/D-02):

- Look up pid from registry (or from session_state.process_pid as fallback)
- If pid exists: call `treeKill(pid, 'SIGTERM')` (tree-kill handles Windows process trees)
- Wrap treeKill in a Promise with 5s timeout; if SIGTERM doesn't work within 5s, retry with SIGKILL
- Remove from registry
- Update DB: `status='frozen', frozen_at=now, process_pid=NULL, updated_at=now`
- Return updated session state
- If no process running: just update DB status (idempotent)

4. **resumeSession(sessionId)** (D-01):

- Read session_state from DB to get provider, project_id
- Look up project directory from projects table
- Spawn new process using cross-spawn (reuse existing spawn patterns from sessionManager.js)
- Register the new process
- Update DB: `status='active', frozen_at=NULL, updated_at=now`
- Return updated session state with new pid

5. **archiveSession(sessionId)** (D-05):

- If process running: kill it first (same as freeze)
- Update DB: `status='archived', archived_at=now, process_pid=NULL, updated_at=now`
- Return updated session state

6. **deleteSession(sessionId)** (D-22 soft-delete):

- If process running: kill it first
- Update DB: `is_deleted=1, process_pid=NULL, updated_at=now` (soft-delete, DO NOT use DELETE FROM)
- Remove from registry
- Return success

7. **getSessionState(sessionId)**: Read from session_state table, return object

8. **listSessionsByProject(projectId, includeDeleted=false)**:

- Query session_state WHERE project_id=? AND (is_deleted=0 OR includeDeleted)
- Order by updated_at DESC

Use `const db = require('../database/db.js')` for database access.
Use `const treeKill = require('tree-kill')` for process termination.
Use `const crossSpawn = require('cross-spawn')` for process spawning.

Error handling: wrap treeKill in try/catch — process may already be dead (ESRCH). Log but don't throw.

<task type="auto">
  <name>Task 2: Create session lifecycle REST endpoints + WebSocket broadcasts</name>
  <files>server/routes/sessionLifecycle.js, server/sessionManager.js</files>
  <action>
  1. Create `server/routes/sessionLifecycle.js`:
  - `POST /api/sessions/:sessionId/freeze` → calls `sessionLifecycleService.freezeSession`
  - `POST /api/sessions/:sessionId/resume` → calls `sessionLifecycleService.resumeSession`
  - `POST /api/sessions/:sessionId/archive` → calls `sessionLifecycleService.archiveSession`
  - `DELETE /api/sessions/:sessionId` → calls `sessionLifecycleService.deleteSession`
  - `GET /api/sessions/:sessionId/state` → calls `sessionLifecycleService.getSessionState`
  - Each mutating endpoint broadcasts WebSocket message after DB update:
    ```js
    wss.broadcast(JSON.stringify({
      type: 'session_state_changed',
      sessionId,
      status: newState.status,
      timestamp: new Date().toISOString()
    }));
    ```
  - Input validation: sessionId must be string, non-empty
  - Error responses: 404 if session not found, 409 if invalid state transition (e.g., freeze an already-frozen session), 500 for process errors
  - Mount in Express app: `app.use('/api/sessions', sessionLifecycleRouter)`

2. Modify `server/sessionManager.js`:

- In existing `createSession()` or wherever new sessions are spawned, add:
  - Call `sessionLifecycleService.registerProcess(sessionId, childProcess.pid, provider)`
  - Ensure new sessions get an initial `session_state` row with `status='active'`
- Add `on('exit')` handler to child processes:
  - When process exits unexpectedly, update session_state to frozen
  - Broadcast `session_state_changed` via WebSocket
- Keep existing in-memory message storage intact — this plan only adds process lifecycle tracking, not message management

State machine transitions (enforce in service):

- active → frozen (freeze)
- active → archived (archive)
- frozen → active (resume)
- frozen → archived (archive)
- archived → active (resume — un-archive)
- any → deleted (soft-delete)
  Invalid transitions return 409.
