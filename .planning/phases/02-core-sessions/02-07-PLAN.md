  <files>server/database/migrations/002-fts5-search.js, server/services/searchService.js, server/routes/search.js</files>
  <action>
  1. Create `server/database/migrations/002-fts5-search.js`:
  - Migration that creates the FTS5 virtual table if it doesn't exist:
    ```sql
    CREATE VIRTUAL TABLE IF NOT EXISTS session_search USING fts5(
      session_id UNINDEXED,
      title,
      content,
      content='',
      contentless_delete=1,
      prefix='2 3',
      tokenize='unicode61'
    );
    ```
  - Register this migration in the existing migration system in db.js's `runMigrations()`
  - The FTS5 module is built into better-sqlite3's bundled SQLite — no extensions needed

2. Create `server/services/searchService.js`:

- `indexSession(sessionId, title, content)`:
  - Delete existing entry first (contentless-delete mode requires explicit delete before re-insert)
  - Insert new entry: `INSERT INTO session_search(session_id, title, content) VALUES (?, ?, ?)`
  - Content = concatenation of session messages (plain text, strip markdown/code blocks)
- `removeFromIndex(sessionId)`:
  - Must provide old column values for contentless-delete mode:
  - Read current row values, then: `INSERT INTO session_search(session_search, session_id, title, content) VALUES ('delete', old_sid, old_title, old_content)`
  - Wrap in try/catch — index entry may not exist
- `search(query, projectId, limit=20)`:
  - Sanitize query: escape FTS5 special chars (`"`, `*`, `AND`, `OR`, `NOT`, `NEAR`)
  - Build FTS5 MATCH query with prefix matching: append `*` for partial word match
  - Join with session_state to filter by project_id and exclude is_deleted=1:
    ```sql
    SELECT ss.session_id, ss.status, ss.provider, rank
    FROM session_search fs
    JOIN session_state ss ON fs.session_id = ss.session_id
    WHERE session_search MATCH ?
      AND ss.project_id = ?
      AND ss.is_deleted = 0
    ORDER BY rank
    LIMIT ?
    ```
  - Return array of { sessionId, status, provider, rank }
  - NOTE: highlight()/snippet() NOT available in contentless mode — return session_id only, let frontend display from its already-loaded data
- `reindexAll()`:
  - Utility function to rebuild entire FTS5 index from session_state + message files
  - Read message history files to extract content
  - Batch insert all sessions
  - Used for initial setup or recovery

3. Create `server/routes/search.js`:

- `GET /api/search?q=<query>&projectId=<id>&limit=20`:
  - Validate: q must be non-empty string, projectId must be integer
  - Call `searchService.search(q, projectId, limit)`
  - Return JSON array of results with session metadata
- `POST /api/search/reindex`:
  - Triggers full reindex (admin/recovery operation)
  - Returns count of indexed sessions
- Mount: `app.use('/api/search', searchRouter)`

Query sanitization is CRITICAL — FTS5 MATCH syntax can throw on malformed queries. Wrap in try/catch and return empty results on parse error rather than 500.
