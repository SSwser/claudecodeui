Create `docs/i18n-key-migration-map.md`. This file is the authoritative reference for the
i18n migration per D-07 and D-08. It must contain:

**Section 1 — Naming Convention (per D-07):**

```
## Naming Convention

Pattern: <namespace>.<component-or-section>.<key>

Rules:
1. All lowercase, dot-separated segments
2. Namespace = file name (common, auth, chat, sidebar, settings, codeEditor, tasks)
3. Component or section = React component name or logical grouping (camelCase → kebab-case)
4. Key = brief English description, snake_case
5. Max three segments: namespace.section.key
   Exception: four segments allowed for deeply nested UI: namespace.screen.section.key
6. No abbreviations — prefer full words (button_label not btn_lbl)
7. Error keys suffix: .error (e.g., auth.login.password_error)
8. Placeholder / dynamic suffix: wrap in {{}} in value (standard i18next)

Bad examples → Good examples:
  settings.sessionSettings → settings.session.title
  common.loading → common.status.loading
  auth.loginError → auth.login.password_error
```

Read all 7 en locale JSON files (`src/i18n/locales/en/*.json`) and for each top-level key

<task type="auto" tdd="false">
  <name>Task 2: Implement CI hardcoded string detection script</name>
  <files>scripts/check-hardcoded-strings.cjs, package.json</files>
  <action>
Create `scripts/check-hardcoded-strings.cjs` — a Node.js CommonJS script (no external deps)
that scans `src/**/*.{tsx,jsx}` files for JSX text content that is NOT wrapped in a
translation call.

**Detection strategy (regex-based, no AST):**

Detect lines containing JSX text nodes that appear to be human-readable UI strings:
```js
// Pattern: standalone text content in JSX that is longer than 3 chars,
// not inside {}, not a component prop string value, not in a comment
```

A violation is a line that:
1. Contains `>SomeText<` or `> SomeText ` in JSX context (angle-bracket-enclosed text)
2. The text is 4+ characters
3. The text is not `{t(...)}`  or `{i18n.t(...)}` or a JSX interpolation `{...}`
4. The text is not a pure number, URL, kebab-slug, or single symbol

**Allowlist (hardcoded in script, configurable via `I18N_ALLOWLIST` env var pointing to JSON):**
```js
const DEFAULT_ALLOWLIST = [
  // Technical strings that should not be translated
  /^\d+(\.\d+)?$/,          // pure numbers
  /^https?:\/\//,           // URLs
  /^[a-z0-9-_]+$/,          // slugs, IDs, enum values
  /^v\d+\.\d+/,             // version strings
  /^[A-Z_]+$/,              // constants
  /^#[0-9a-fA-F]{3,8}$/,    // hex colors  
  /^\s*$/,                  // whitespace only
];
```

**Ignore patterns (file-level):**
- Files matching `*.test.*`, `*.spec.*`, `*.stories.*`
- Any line containing `// i18n-ignore`

**Output format:**
```
Checking src/ for hardcoded UI strings...

VIOLATION: src/components/sidebar/view/Sidebar.tsx:42
  > Settings
  Use: t('sidebar.navigation.settings') or add // i18n-ignore

VIOLATION: src/components/auth/view/LoginForm.tsx:88
  > Email Address
  Use: t('auth.login.email_label') or add // i18n-ignore

Found 2 violation(s). Run with I18N_ALLOWLIST=path/to/allowlist.json to add exceptions.
```

**Exit behavior:**
- Violations found → `process.exit(1)`
- No violations → `process.exit(0)` with "No hardcoded string violations found."

**Update `package.json` scripts section — add:**
```json
"lint:i18n": "node scripts/check-hardcoded-strings.cjs"
```

Place after `"lint:fix"` in the scripts block.

**Security note:** The script reads the filesystem using `fs.readdirSync` / `fs.readFileSync`
with paths derived from `process.cwd()` — never from user input. No shell execution,
no exec/spawn with untrusted data.
