# Phase 999.1: Dev Login Skip or Credential Management - Context

**Gathered:** 2026-04-11
**Status:** Ready for planning

<domain>
## Phase Boundary

开发环境登录跳过机制——通过 `DEV_AUTO_LOGIN` 环境变量在开发/测试环境中自动绕过登录流程，减少开发调试和人工 UAT 中的认证摩擦。

**核心使用场景（触发此 phase 的直接动机）：** 对 design-md（999.2）等设计系统变更进行真实登录态的人工 UAT 时——测试 chat 操作、settings 调整、sidebar 重命名等完整业务流——每次重启 dev server 都需要手动过登录，严重阻碍迭代效率。`DEV_AUTO_LOGIN` 让开发者/测试者进入 app 后直接处于已登录状态，以真实应用态（而非 fixture 或 mock）验证业务流。

不涉及生产环境的认证流程变更或第三方 OAuth 集成。

</domain>

<decisions>
## Implementation Decisions

### 方案选择

- **D-01:** 采用混合方案——`DEV_AUTO_LOGIN` 环境变量跳过登录 + 现有 JWT auto-refresh 机制处理 token 持久化，不额外实现持久化逻辑。
- **D-02:** 仅需 `DEV_AUTO_LOGIN=true` 单一环境变量，默认用户名/密码硬编码为 dev/dev。不引入 DEV_USERNAME、DEV_PASSWORD 等额外变量。

### 安全边界

- **D-03:** 双层保护——前端通过 Vite `define` 在生产构建时移除开发代码路径（dead code elimination），后端通过环境变量运行时检查。两层同时生效，确保开发绕过逻辑不可能泄漏到生产环境。

### 实现层级

- **D-04:** 复用 `IS_PLATFORM` 的双层绕过模式——server 端 `authenticateToken` 检测 `DEV_AUTO_LOGIN` 时自动注入用户，前端 `AuthContext`/`ProtectedRoute` 检测开发模式时跳过 LoginForm。前后端对称处理。
- **D-05:** 抽取通用 `shouldSkipAuth()` 函数，内部检查 `IS_PLATFORM || DEV_AUTO_LOGIN`，统一两种绕过场景的判断逻辑，减少重复代码。

### 开发体验

- **D-06:** 自动登录时显示轻量 UI 提示（toast 或 badge），告知当前为开发模式自动登录，防止与正常登录混淆。
- **D-07:** 如果数据库无用户（全新环境），自动创建默认 dev/dev 用户并登录。已有用户则使用第一个用户。

### 测试环境兼容

- **D-08:** 测试环境（Playwright E2E）复用 `DEV_AUTO_LOGIN` 机制，简化测试的 auth 设置。

### WebSocket 认证

- **D-09:** WebSocket 认证（`authenticateWebSocket`）交由 agent 自行决定处理方式。已有 `IS_PLATFORM` 的 WebSocket 绕过逻辑作为参考，`shouldSkipAuth()` 函数自然覆盖此场景。

### 人工 UAT 支持

- **D-10:** 人工 UAT 场景（如验证 999.2 设计系统变更）是此 phase 的首要驱动场景。`DEV_AUTO_LOGIN` 必须确保开发者在真实已登录应用态下可以不受阻碍地进行以下操作：chat composer 输入与消息发送流、settings 各 tab 调整、sidebar 项目/session 重命名。这些流程需要完整的 WebSocket 连接 + API 鉴权，单纯跳过登录表单不够——必须注入有效 session token，使后续所有 API 调用都以已认证用户身份执行。

### Agent's Discretion

- WebSocket 认证绕过的具体实现细节
- toast vs badge 的具体 UI 形式选择
- 默认 dev 用户的自动创建时机（server 启动时 vs 首次请求时）
- Vite define 的具体变量命名

</decisions>

<code_context>

## Existing Code Insights

### Reusable Assets

- **IS_PLATFORM 模式**: `server/middleware/auth.js` 中完整的双层（HTTP + WebSocket）绕过实现，可作为 DEV_AUTO_LOGIN 的直接参考模板
- **userDb.getFirstUser()**: 已有获取第一个用户的方法，DEV_AUTO_LOGIN 可直接复用
- **userDb.createUser()**: 已有用户创建方法，自动创建 dev 用户可复用
- **generateToken()**: 已有 JWT token 生成函数

### Established Patterns

- **环境标志模式**: `IS_PLATFORM` 通过 `process.env.VITE_IS_PLATFORM === 'true'` 判断，前后端共享同一环境变量前缀 `VITE_`
- **认证中间件模式**: `authenticateToken` 中 IS_PLATFORM 检查在最前面，DEV_AUTO_LOGIN 应遵循相同模式
- **前端路由守卫**: `ProtectedRoute` 使用 `IS_PLATFORM` 条件分支跳过 LoginForm

### Integration Points

- `server/middleware/auth.js` — authenticateToken、authenticateWebSocket 需增加 DEV_AUTO_LOGIN 分支
- `src/components/auth/view/ProtectedRoute.tsx` — 需增加 DEV_AUTO_LOGIN 条件跳过
- `src/components/auth/context/AuthContext.tsx` — 可能需要在 checkAuthStatus 中处理开发模式
- `src/constants/config.ts` — 需要增加 DEV_AUTO_LOGIN 常量（类似 IS_PLATFORM）

</code_context>

<specifics>
## Specific Ideas

- 复用 IS_PLATFORM 的代码模式和结构，保持代码一致性
- shouldSkipAuth() 统一函数将 IS_PLATFORM 和 DEV_AUTO_LOGIN 合并，减少未来维护成本
- 安全双层保护：前端 Vite define + 后端 env var，两层独立互不依赖

</specifics>
