| Option                 | Description                                                                                 | Selected |

## Update: 2026-04-11（Context 追加）

**触发：** 999.2 设计系统（design-md）执行完成，进入人工 UAT 阶段时发现登录摩擦。

**补充决策 D-10：** 人工 UAT 是本 phase 的首要驱动场景

| 场景               | 需求                                                  |
| ------------------ | ----------------------------------------------------- |
| chat 业务流 UAT    | 进入已登录应用态后直接操作 chat composer、发送消息    |
| settings 调整 UAT  | 在各 settings tab 中实际操作，验证 design-md 视觉变更 |
| sidebar 重命名 UAT | 在真实应用态下重命名 project/session，验证控件行为    |

**关键补充：** 单纯跳过登录表单不够——这些流程依赖 WebSocket 连接和 API 鉴权。`DEV_AUTO_LOGIN` 必须注入有效 session token，确保进入应用后所有 API 调用都以已认证用户身份执行。

**User input:** 999.2 的 UAT 通过 fixture + Playwright 截图验证视觉，但真实业务流（chat、settings、sidebar 重命名）仍需登录态下人工验证，每次重启 dev server 都要手动过登录，严重阻碍迭代效率。
