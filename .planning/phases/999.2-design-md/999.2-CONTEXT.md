# Phase 999.2: 参考 design.md 统一视觉风格 - Context

**Gathered:** 2026-04-11
**Status:** Ready for planning

<domain>
## Phase Boundary

以 DESIGN.md 中的 Raycast 风格设计系统为基准，全面统一应用视觉语言——色彩 token、排版系统、阴影层级、边框模式、间距比例、圆角比例、按钮变体及交互模式。覆盖 dark mode 和 light mode。不涉及功能逻辑、状态管理或动效系统的变更。

</domain>

<decisions>
## Implementation Decisions

### 色彩对齐策略
- **D-01:** 直接替换 `.dark {}` 中的 CSS 变量值为 DESIGN.md 色板（`#07080a` background、`#101111` card surface、`hsl(195, 5%, 15%)` border 等），全局即时生效，不引入过渡层。
- **D-02:** 同步调整 light mode——基于 DESIGN.md dark 色板做明暗对称映射，一步到位更新 `:root` 变量值。
- **D-03:** 引入独立 `--brand` / `--brand-foreground` CSS 变量用于 Raycast Red (`#FF6363`)，与 `--destructive` token 分离。品牌色用于 CTA 和品牌标识场景，destructive 保留用于错误/危险状态。

### 排版系统迁移
- **D-04:** 本地托管 Inter + GeistMono 字体（woff2 格式放入 `public/fonts/`），通过 `@font-face` 声明加载。零网络依赖，FOUT 可控。
- **D-05:** 全局 `--font-weight-normal` 从 400 改为 500（medium），提升 dark mode 可读性。
- **D-06:** letter-spacing 通过 Tailwind 自定义 `tracking-*` class 按组件应用（body +0.2px、button/nav +0.3px），不全局设置。

### 阴影与深度层级
- **D-07:** 引入精简版 3 级阴影系统（subtle、ring、button），Key 和 Floating 后续按需添加。不一次引入全部 6 级。
- **D-08:** 阴影通过 cva 变体系统管理（`elevation: 'subtle' | 'ring' | 'button'`），与现有组件变体模式一致。
- **D-09:** 卡片边框采用 DESIGN.md 的 rgba 白边框 + 双环模式（`rgba(255,255,255,0.06)` border + `0px 0px 0px 1px` outer ring + inset ring）。

### 迁移范围与节奏
- **D-10:** Token 先行，组件跟进——第一步替换 CSS 变量（色彩、字体、字重、圆角），第二步更新组件层（阴影、边框、letter-spacing、hover 模式）。
- **D-11:** 复用 Phase 4 已有的 Playwright 视觉回归基线，更新截图对比验证视觉变更。
- **D-12:** 引入 DESIGN.md 圆角比例尺，扩展 `--radius` 为多级别 token（micro 2-3px、small 4-6px、medium 8px、large 12-16px、pill 86px+）。

### 交互模式
- **D-13:** 全局采用 opacity hover 模式（hover: opacity 0.6 过渡），替代当前 background 变化的 hover 模式。所有按钮、卡片、链接统一。

### 间距系统
- **D-14:** 切换为 px 基础 spacing token（`--spacing-1: 4px`、`--spacing-2: 8px`...），与 DESIGN.md 8px base unit 完全一致，替代现有 rem 基础值。

### 按钮变体
- **D-15:** 重新映射现有 Button 变体到 DESIGN.md 风格——default→Primary Pill（透明底 + 白字 + 86px圆角 + inset shadow）、secondary→Secondary（透明底 + 白字 + 6px圆角 + rgba border）、ghost→Ghost（无底无边 + 灰字→白字）、CTA→半透明白底深色字。更新样式但保持 variant API 兼容。

### OpenType Features
- **D-16:** OpenType features（calt、kern、liga、ss03）通过 Tailwind 自定义 class 按组件应用，不在 body 全局设置。

### 总体方针
- **D-17:** 不做向后兼容补丁处理。直接基于决策选择最优解实现，不保留旧样式的过渡层或兼容 shim。

</decisions>

## Existing Code Insights

### Reusable Assets
- `src/index.css` `:root` / `.dark` 中已有完整的语义 token 结构（background、foreground、card、border、surface-*、sidebar-*），变量值替换即可全局生效
- `tailwind.config.js` 已有 `hsl(var(--token))` 桥接模式，扩展 shadow/tracking/radius 遵循相同模式
- `src/shared/view/ui/Button.tsx` 和 `src/components/ui/button.tsx` 已使用 cva() + cn() 变体模式，样式重映射不需改变架构
- Phase 4 已配置 Playwright 视觉回归基线，可直接更新截图

### Established Patterns
- Tailwind-first styling + CSS 变量语义 token 是项目标准
- cva() 变体 + cn() 组合用于所有共享组件
- `@layer base` 中定义全局样式规则
- Feature UI 保持 feature-folder 所有权，共享组件集中在 `src/components/ui/` 和 `src/shared/view/ui/`

### Integration Points
- Token 替换：`src/index.css`（CSS 变量值）、`tailwind.config.js`（Tailwind 扩展）
- 字体加载：`public/fonts/`（woff2 文件）、`src/index.css`（@font-face 声明）、`index.html`（preload）
- 组件样式：所有使用 `bg-background`、`text-foreground`、`border-border` 等语义 class 的组件自动继承 token 变更
- 按钮变体：`src/components/ui/button.tsx` 的 cva 变体定义

</code_context>

<specifics>
## Specific Ideas

- DESIGN.md 的 `#07080a` 近黑蓝底是核心视觉特征，不能用纯黑替代
- Raycast Red 作为"标点"式品牌色——仅在关键 CTA 和品牌标识处出现，不泛滥使用
- macOS-native 多层阴影（inset + outer）是 Raycast 风格的签名特征，必须正确实现
- Inter 字体的正值 letter-spacing (+0.2px) 在 dark UI 中提供独特的通透感，是差异化设计要素
- 直接替换，不做兼容过渡——本次迁移是一步到位的视觉对齐

</specifics>

<deferred>
## Deferred Ideas

- **全局动效库引入** — 用户希望引入动效库统一实现全局动效。这是一个独立能力（动效系统），超出视觉风格对齐范围，建议作为独立阶段规划。
- **状态管理重构（hook first）** — 用户提到状态管理很重要，希望采用 hook first 方式。这是架构层面决策，不属于视觉风格迁移范围。
- **Floating / Key 级阴影** — DESIGN.md 定义了 6 级阴影，本阶段只引入 3 级（subtle、ring、button），高级阴影（key、floating）后续按需添加。

</deferred>
