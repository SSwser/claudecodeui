# Phase 999.2 - UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Stack Assumptions

- This phase is a visual-system alignment backlog item, not a feature-delivery phase. It standardizes tokens, depth, radius, and component appearance without changing product flows or state architecture.
- Frontend stack remains React 18 + Vite + React Router.
- Styling remains Tailwind CSS + semantic CSS variables from `src/index.css`; no parallel token system is introduced.
- Existing local primitives in `src/shared/view/ui` and `src/components/ui` remain the implementation entrypoints.
- Icon system remains `lucide-react` plus existing provider logo components.
- Font stack changes in this phase are limited to locally hosted Inter + GeistMono and Tailwind/class-based application of tracking/OpenType decisions.

### Radius Tiers

| Token             | Value | Usage                                              |
| ----------------- | ----- | -------------------------------------------------- |
| `--radius-micro`  | 2px   | Tiny indicators, inline code, micro status dots    |
| `--radius-small`  | 6px   | Secondary buttons, badges, tags, keycaps           |
| `--radius-medium` | 8px   | Inputs, selects, compact containers                |
| `--radius-large`  | 12px  | Standard cards, dialogs, screenshots               |
| `--radius-xl`     | 16px  | Hero cards, major grouped sections                 |
| `--radius-pill`   | 86px  | Primary pill buttons, nav CTAs, ghost pill actions |

### Shadow & Elevation

| Level | Token Name | Value                                                                                                                                   | Usage                                                 |
| ----- | ---------- | --------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------- |
| 0     | `none`     | `none`                                                                                                                                  | Page background and flat layout regions               |
| 1     | `subtle`   | `rgba(0, 0, 0, 0.28) 0px 1.189px 2.377px`                                                                                               | Minimal lift for inline controls and compact surfaces |
| 2     | `ring`     | `rgb(27, 28, 30) 0px 0px 0px 1px, rgb(7, 8, 10) 0px 0px 0px 1px inset`                                                                  | Card containment, dialog frames, elevated list rows   |
| 3     | `button`   | `rgba(255, 255, 255, 0.05) 0px 1px 0px 0px inset, rgba(255, 255, 255, 0.25) 0px 0px 0px 1px, rgba(0, 0, 0, 0.2) 0px -1px 0px 0px inset` | Default/CTA buttons and pill actions                  |

Card edge treatment is not optional in dark mode: standard cards use `1px solid rgba(255,255,255,0.06)` plus the `ring` elevation to preserve the Raycast-style double-ring silhouette.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage                                     |
| ----- | ----- | ----------------------------------------- |
| xs    | 4px   | Icon gaps, inline padding, badge inset    |
| sm    | 8px   | Dense control spacing, input inner rhythm |
| md    | 16px  | Default card padding and block spacing    |
| lg    | 24px  | Section padding, grouped form spacing     |
| xl    | 32px  | Layout gaps, medium panel separation      |
| 2xl   | 48px  | Major section breaks                      |
| 3xl   | 64px  | Page-level vertical rhythm                |

Exceptions: none. `44px` minimum touch target remains an accessibility constraint, not a spacing token. Internal CSS spacing tokens should be expressed in px and aligned to the 8px base system.

## Typography

| Role    | Size | Weight | Line Height |
| ------- | ---- | ------ | ----------- |
| Body    | 16px | 500    | 1.5         |
| Label   | 14px | 500    | 1.4         |
| Heading | 20px | 600    | 1.2         |
| Display | 28px | 600    | 1.2         |

### Typography Application Rules

- Base UI font is Inter; code and terminal surfaces use GeistMono.
- Body tracking is `+0.2px`; button and nav tracking is `+0.3px`.
- `--font-weight-normal` is redefined to `500` in this phase. Regular `400` is not the default body weight.
- OpenType features `calt`, `kern`, `liga`, `ss03` are enabled through opt-in utility classes, not globally on `body`.
- Display surfaces should not introduce additional sizes beyond the four locked sizes above during this phase.

## Color

| Role            | Value                                            | Usage                                                                                              |
| --------------- | ------------------------------------------------ | -------------------------------------------------------------------------------------------------- |
| Dominant (60%)  | `#07080a` in dark mode / `#f6f7f8` in light mode | App background, page void, shell base, large canvases                                              |
| Secondary (30%) | `#101111` in dark mode / `#ffffff` in light mode | Cards, dialogs, sidebar shells, navigation surfaces                                                |
| Accent (10%)    | `#FF6363` (`--brand`)                            | Brand punctuation, final apply-visual-system CTA, migration highlight badge, selected brand marker |
| Destructive     | `hsl(0 100% 69%)` dark / `hsl(0 84% 60%)` light  | Reset, remove, destructive confirmations, regression-failure emphasis                              |

Accent reserved for: product brand marks, one high-emphasis migration CTA per screen, visual diff highlight badges, and rare status markers that indicate style-system adoption. Accent is never the default fill for all interactive elements. Focus, link, and selected-input states use the blue `--ring` family instead of `--brand`.

## Component Visual Mapping

| Surface / Component         | Contract                                                                                                                                                                     |
| --------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Button` `default`          | Maps to Primary Pill: transparent or near-transparent dark surface, white text, `--radius-pill`, `button` elevation, hover via `opacity: 0.6`, no hue-shift hover fill       |
| `Button` `secondary`        | Maps to Secondary Button: transparent surface, white text, `--radius-small`, `1px solid rgba(255,255,255,0.1)` border, `subtle` elevation, hover via opacity only            |
| `Button` `ghost`            | Maps to Ghost Pill: no fill, no visible border, idle text `#6a6b6c`, hover text to white, `--radius-pill`, no background flash on hover                                      |
| `Button` `outline`          | Maps to bordered neutral action: same chrome as secondary, but reserved for inline utilities and field-adjacent actions rather than primary screen CTA                       |
| `Button` `destructive`      | Uses destructive token family, red border or red-tinted ring, destructive copy only, hover remains opacity-based rather than red background flood                            |
| Future `Button` `cta`       | If introduced, uses semi-transparent white background, dark text `#18191a`, `--radius-pill`, `button` elevation, white-on-white hover brightening                            |
| Cards / panels              | `#101111` dark surface, `--radius-large` or `--radius-xl`, `rgba(255,255,255,0.06)` edge, `ring` elevation; no flat border-only cards                                        |
| Inputs / selects / combobox | `#07080a` dark field fill, `--radius-medium`, `rgba(255,255,255,0.08)` border, text `#f9f9f9`, placeholder `#9c9c9d`, focus ring uses blue `--ring` glow                     |
| Dialogs / popovers          | Same card surface contract as elevated cards, `--radius-large`, `ring` elevation, no brighter modal surface that breaks the dark stack                                       |
| Badges / tags               | `#1b1c1e` surface, `--radius-small`, 14px label rhythm, no saturated accent fills except explicit brand or destructive badge states                                          |
| Nav links / tabs            | Idle text `#9c9c9d`, hover/active text white, opacity-driven hover, active state can combine white text plus blue focus/ring or subtle brand marker, but not solid red fills |
| Links                       | Text-first interaction using blue `--ring` family or white emphasis, underline reserved for content links, not for shell tabs or buttons                                     |

### Interaction Rules

- Global hover language is opacity-first. Buttons, cards, links, and compact actions use opacity reduction or subtle text brightening instead of background-color swaps.
- Focus-visible states use the blue `--ring` family. Brand red does not replace focus indication.
- Disabled state uses reduced opacity and muted foreground only; disabled controls do not get new border colors.
- This phase does not introduce a motion system. Any existing transitions remain short and subordinate to the opacity-first contract.

### Visual Hierarchy Rules

- Migration-facing screens follow a fixed reading order: first the migration status summary, then the primary "apply visual system" CTA, then any diff, risk, or regression guidance.
- Brand red is reserved for a single focal action or marker per screen. Supporting controls should derive emphasis from contrast, spacing, and ring treatment instead of competing accent fills.
- If icon-only actions are introduced during migration, each control must expose a visible tooltip or equivalent text label and an explicit `aria-label`; no icon-only affordance may ship without text fallback.

## Copywriting Contract

| Element                  | Copy                                                                                                |
| ------------------------ | --------------------------------------------------------------------------------------------------- |
| Primary CTA              | 应用视觉系统                                                                                        |
| Empty state heading      | 没有待对齐的视觉项                                                                                  |
| Empty state body         | 当前界面已经使用最新 token 与组件映射；如需继续迁移，请检查旧样式组件或新增视觉回归基线。           |
| Error state              | 无法应用视觉 token。请先检查 `src/index.css`、`tailwind.config.js` 与视觉回归差异，再重新执行迁移。 |
| Destructive confirmation | 重置视觉映射: 此操作会撤回当前品牌与组件样式对齐，恢复旧视觉表现并影响截图基线，确认继续？          |

### Migration-Facing Copy Rules

- Copy must describe migration state, not end-user product functionality.
- Empty states refer to token alignment, legacy component cleanup, or regression baseline status.
- Error states must name the next diagnostic step: token file, Tailwind bridge, or screenshot baseline.
- Destructive confirmations must call out design-regression impact explicitly because this phase changes shared primitives globally.
