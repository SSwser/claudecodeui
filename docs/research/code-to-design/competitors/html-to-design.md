## 核心功能

### 1. 网页转换为 Figma 设计

- 将任何网站转换为可编辑的 Figma 设计
- 保持层级结构和布局

### 2. 多种导入方式

| 方式              | 说明                          |
| ----------------- | ----------------------------- |
| URL               | 直接输入网页地址              |
| Chrome 扩展       | 支持私有/需要登录的页面       |
| HTML/HTM 文件     | 上传本地文件                  |
| MHTML 文件        | 完整网页存档                  |
| ZIP 文件          | 打包的网页资源                |
| EML 邮件          | 邮件模板导入                  |
| **Editor 标签页** | 🆕 直接粘贴 HTML/CSS 代码导入 |

### 3. 响应式捕获

- 支持多视口尺寸捕获: mobile, desktop, tablet
- 可同时生成多个视口的设计

### 4. MCP 支持 (新功能)

- "Fastest MCP server!"
- 支持 Claude Desktop 和 Cursor
- 可通过 AI 生成设计后发送到 Figma
- 这意味着: **代码 → AI → html.to.design → Figma** 的工作流已可行

### 5. 批量处理 (Pro)

- 批量 URL 导入
- 重新导入功能

## 与 story.to.design 的关系

**同一家公司 (‹div›RIOTS)** 出品:

- `html.to.design` — 网页/HTML → Figma (2.2M 用户)
- `story.to.design` — Storybook → Figma (11K 用户)

这表明 ‹div›RIOTS 在 "代码世界 → 设计世界" 方向有深厚积累，但以**两个独立插件**的形式运营，未整合为平台。

## 技术架构分析

### 工作原理（推断）

1. 获取目标网页的 DOM
2. 解析 CSS 计算样式
3. 渲染/截图
4. 构建对应的 Figma 节点树
5. 通过 Figma Plugin API 写入 Figma 文件

### 技术限制

- **单向**: 仅 HTML → Figma，无反向同步
- **快照式**: 导入的是时间点快照，不是实时同步
- **不保留语义**: 导入后的 Figma 层可能不够语义化
- **样式损失**: 复杂 CSS 效果（动画、伪元素等）可能无法完整转换
- **组件关系**: 导入的不是可复用组件，是扁平图层
- **无 Design Token 映射**: 不会将 CSS Variables 转为 Figma Variables

## 与我们产品愿景的关系

### 竞争维度

| 维度              | 重叠度 | 说明                        |
| ----------------- | ------ | --------------------------- |
| 代码→设计         | 🔴 高  | 核心功能就是 HTML→Figma     |
| Figma 集成        | 🔴 高  | 原生 Figma 插件             |
| AI 驱动           | 🟡 中  | MCP 支持，但不是 AI-first   |
| 仓库直连          | 🟢 低  | 不连接代码仓库              |
| Design Token 同步 | 🟢 低  | 不做 token 同步             |
| 本地部署          | 🟢 低  | Figma 插件，依赖 Figma 平台 |

### 差异化机会

1. **html.to.design 是"快照"工具**，我们是**持续同步平台**
2. 不处理 **Design Token / Variables 映射**
3. 不连接 **代码仓库** — 每次需要手动导入
4. 不生成 **可复用 Figma 组件** — 只是图层快照
5. 不支持 **反向同步** (Figma→代码)

### 可利用的价值

- **html.to.design 可作为我们工作流的一部分**: 用它做初始导入，然后我们的平台接管持续同步
- **验证了市场需求**: 2.2M 用户证明"代码→设计"需求巨大
- **MCP 集成**: 可以在 AI 工作流中串联使用

### 潜在威胁

- 如果 ‹div›RIOTS 整合 html.to.design + story.to.design + Design Token 功能 → 形成平台
- 2.2M 用户基础巨大,如果他们做增量同步功能 → 先发优势明显
- 母公司同时拥有 Storybook→Figma 和 HTML→Figma → 可能形成更完整的解决方案

## 关键洞察

1. **2.2M 用户 = 强烈的"代码→设计"需求验证**
2. **$18/月的价格对于工具类插件来说不低** — 用户愿意为此付费
3. **‹div›RIOTS 拥有两个互补产品但未整合** — 这是市场空白
4. **新增 MCP 支持表明方向正确** — AI 驱动的设计自动化是趋势
5. **作为"快照工具"而非"同步平台"是其根本局限**
6. **可以作为我们产品 MVP 阶段的集成组件**
